# План проекта «Цифровой деканат будущего»

Статус: согласован 11.11.2026.

## 1. Цель
Сделать рабочий прототип личного кабинета студента для MGIMO AI Challenge (номинация «Вайб-кодинг»).

- Приём работ: до 22.11.2026, 23:59 МСК.
- Прототип должен работать до 28.11.2026 и открываться из России без VPN.

## 2. Решения
| Решение | Значение |
|---|---|
| Стек | Python 3.12 + Django 5.2 LTS, шаблоны Django, без REST API и без SPA |
| Хостинг | Сначала локально, потом арендованный сервер в РФ |
| БД | SQLite локально, PostgreSQL на сервере |
| Процесс | Waterfall для этапов, Agile-спринты внутри этапа реализации |
| Интерфейс | Ретро / пиксель-арт, делаем в конце. Вёрстка mobile-first с первого спринта; пиксельный шрифт только для заголовков |
| Деплой | Пробный деплой 17.11, не в конце |
| Сотрудник деканата | Свои простые страницы (чат, заявки) + админка Django для данных |
| Чат | Страница сама запрашивает новые сообщения раз в N секунд (HTML-фрагмент от Django, без JSON-API) |
| Карта | Условная SVG-схема вымышленного вуза, один корпус. Если успеем — несколько этажей с переключением |
| Описание процесса | Ведём с первого дня в `docs/process/` |
| Команда ИИ | Тимлид, Планировщик, Ревьюер (Claude Code), Кодер (DeepSeek) |

### Наши дополнительные функции
- Карта аудиторий. Клик по занятию в расписании открывает карту и подсвечивает аудиторию.

- Чат с деканатом.

### Технические требования
- Все сценарии работают на экране шириной от 360 px.
- Студент видит только свои данные. Подстановка чужого ID в адрес не даёт доступ.
- Пароли хранятся только в виде хеша (стандарт Django).
- Ключи и пароли не хранятся в коде и в браузере.
- Только вымышленные данные.
- На сайте есть пометка «концепт для конкурса, не официальный сервис».
- Логотип вуза не используется, логотип делаем свой.
- Шрифты, иконки и картинки берём только с подходящей лицензией.
- Для жюри: минимум 2 аккаунта студентов и аккаунт сотрудника деканата.

## 6a. Недочёты: порядок работы
Технический долг не откладывается. После каждой задачи тимлид готовит задачу `TASK-NNN-FIX` с недочётами и рекомендациями. Пользователь решает, что исправлять. Исправление проходит полный цикл. После закрытия исправлений тимлид сжимает контекст Кодера (`bb thread compact`), но только если последний запрос больше 200 тыс. токенов.

Сейчас: TASK-008 закрыта 15.11, готовится TASK-008-FIX. Контекст Кодера сжат 15.11 после цикла TASK-007 (было 316 тыс.).

### Принятые ограничения
- После перевода студента в другую группу посещения занятий старой группы не показываются (переводов в прототипе нет).
- `seed_demo` удаляет свои демо-изменения расписания массово, в обход проверки удаления. Возможный конфликт команда ловит сразу и останавливается с ошибкой.
- `seed_demo` не обновляет существующие учебные записи, чтобы не затирать правки из админки. Повторный запуск добавляет недостающие записи.
- После миграции `schedule/0004` в уже существующей базе старые изменения расписания один раз показываются как «Новое». На сервере база новая.
- Ссылка с новости на главной не ведёт к записи, если новость старше 30 дней или за пределами 50 записей ленты. С демо-данными в период проверки жюри этого нет.

## 6b. Обязательно при деплое
- За nginx задать `CLIENT_IP_HEADER`. Иначе все клиенты получают IP прокси, и блокировка по «логин + IP» превращается в блокировку по логину: любой сможет заблокировать вход жюри.
- Блокировки при одновременном редактировании работают только на PostgreSQL (SQLite их игнорирует).
- nginx НЕ отдаёт папку `PRIVATE_MEDIA_ROOT` (вложения к заявкам). Файлы скачиваются только через Django с проверкой доступа (TASK-006).
- Резервная копия: папку `PRIVATE_MEDIA_ROOT` копировать вместе с базой. Иначе скачивание вложений после восстановления базы даст ошибку.
- nginx: `client_max_body_size 20m` — иначе загрузка PDF к заявкам (до 3 файлов по 5 МБ) упадёт с ошибкой 413 (TASK-006).
- Запустить `seed_demo` на сервере 22.11 (в день сдачи). Изменения расписания попадут на недели 16–22.11 и 23–29.11, то есть на весь период проверки жюри (23–28.11). Ежедневный cron не нужен.
